## 간단한 GitLab CI/CD 파이프라인 구성하기

GitLab CI/CD는 소프트웨어 개발 프로세스를 자동화하고, 코드의 빌드, 테스트, 배포까지의 과정을 손쉽게 관리할 수 있도록 도와줍니다. <br/>
GitLab의 CI/CD는 `.gitlab-ci.yml` 파일을 사용하여 파이프라인을 구성하고, 이를 통해 개발, 테스트, 배포를 자동화할 수 있습니다.

이번 글에서는 간단한 GitLab CI 파이프라인을 구성하는 방법을 알아보겠습니다.<br/>
이 예제는 코드의 빌드, 테스트, 배포까지 기본적인 흐름을 설정하는 과정입니다.

## :wrench: 사전 작업

GitLab Runner를 설치하고 등록해야 합니다.<br/>
자세한 방법은 [GitLab Runner 설치 및 설정 방법](/blog/gitlab-runner)을 참고하세요.

## 1.`.gitlab-ci.yml` 파일 개요

GitLab CI/CD에서 파이프라인을 정의하는 파일은 `.gitlab-ci.yml` 입니다.<br/>
이 파일에는 실행할 **단계(Stages)** 와 각 단계를 구성하는 **작업(Jobs)** 들을 정의합니다. 각 단계는 순차적으로 실행되며, 각 작업은 해당 단계에서 실행되는 명령어들을 포함합니다.

다음은 간단한 예시로, GitLab CI 파이프라인을 작성한 `.gitlab-ci.yml` 파일입니다.

```yaml
stages: # 파이프라인에서 실행할 단계 정의
  - build
  - test
  - deploy

# 빌드 단계
build_job:
  stage: build
  script:
    - echo "Installing dependencies..."
    - npm install # 의존성 설치
    - echo "Building the project..."
    - npm run build # 빌드 수행

# 테스트 단계
test_job:
  stage: test
  script:
    - echo "Running tests..."
    - npm test # 테스트 실행

# 배포 단계
deploy_job:
  stage: deploy
  script:
    - echo "Deploying to production..."
    - npm run deploy # 배포 수행
  only:
    - main # 'main' 브랜치에서만 배포 작업 실행
```

---

## 2. 단계별 설명

### 2-1 Stages 정의

`.gitlab-ci.yml` 파일의 가장 첫 번째 부분은 stages입니다. 여기에 파이프라인에서
실행할 단계들을 정의합니다. 각 단계는 jobs를 그룹화하는 역할을 합니다. 이번 예제에서는
build, test, deploy 3개의 단계가 정의되어 있습니다.

```yaml
stages:
  - build
  - test
  - deploy
```

### 2-2 Build Job 정의

build_job은 프로젝트를 빌드하는 작업입니다. 이 단계에서는 주로 의존성 설치와 빌드를 수행합니다. `npm install`을 통해 의존성 패키지를 설치하고, `npm run build`로 빌드를 진행합니다.

```yaml
build_job:
  stage: build
  script:
    - echo "Installing dependencies..."
    - npm install # 의존성 설치
    - echo "Building the project..."
    - npm run build # 빌드 수행
```

### 2-3 Test Job 정의

test_job은 빌드가 완료된 후, 테스트를 실행하는 단계입니다. 이 예제에서는 npm test 명령어로 테스트를 실행합니다.

```yaml
test_job:
  stage: test
  script:
    - echo "Running tests..."
    - npm test # 테스트 실행
```

### 2-4 Deploy Job 정의

deploy_job은 배포 작업을 담당합니다. 이 예제에서는 `npm run deploy`를 사용하여 배포를 진행합니다. 중요한 점은, `only: - main` 설정을 통해 **main 브랜치**에서만 배포가 실행되도록 제한하고 있다는 것입니다. 이렇게 설정하면 다른 브랜치에서는 배포 작업이 실행되지 않습니다.

```yaml
deploy_job:
  stage: deploy
  script:
    - echo "Deploying to production..."
    - npm run deploy # 배포 수행
  only:
    - main # 'main' 브랜치에서만 배포 작업 실행
```

---

## 3. 실행 흐름

이 파이프라인은 기본적으로 다음과 같은 흐름으로 진행됩니다:

1. **Build**: `build_job`에서 의존성을 설치하고 프로젝트를 빌드합니다.
2. **Test**: `test_job`에서 빌드된 프로젝트의 테스트를 실행합니다.
3. **Deploy**: `deploy_job`에서 main 브랜치에만 배포 작업을 실행합니다.

---

## 4. 추가 설정

GitLab CI/CD는 매우 유연하게 설정을 추가할 수 있습니다. 예를 들어:

- **병렬 작업**: 여러 작업을 동시에 실행하거나, dependencies를 사용하여 작업 간 의존성을 설정할 수 있습니다.

- **캐시**: 빌드 속도를 빠르게 하기 위해 특정 파일을 캐시할 수 있습니다.

- **환경 변수**: 배포를 위한 비밀 키나 API 키 등을 환경 변수로 설정할 수 있습니다.

---

## 5. 마무리

GitLab CI/CD를 활용하면 코드의 빌드, 테스트, 배포를 자동화할 수 있습니다. 이번 글에서는 간단한 파이프라인을 구성하는 방법을 알아보았습니다. 실제 프로젝트에서는 더 복잡한 설정이 필요할 수 있지만, 기본적인 흐름을 이해하고 이를 확장하는 방법을 익히면 프로젝트 관리를 더욱 효율적으로 할 수 있습니다.
