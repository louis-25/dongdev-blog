Docker를 처음 쓰는 분들을 위해, 설치부터 이미지 빌드/실행, 데이터 영속화, Docker Compose, 베스트 프랙티스까지 빠르게 훑어봅니다. (최신 내용은 Context7 MCP를 통해 Docker 공식 문서를 참고하여 정리했습니다.)

---

## 소개

- **Docker란?** 애플리케이션을 컨테이너라는 표준 단위로 패키징/배포/실행하게 해주는 플랫폼
- **핵심 이점**: 환경 일관성, 빠른 배포, 격리된 실행, 간단한 확장

---

## 설치

### Docker Desktop 설치 (Windows/macOS)

1. Docker Desktop 설치 후 실행
2. 최초 실행 시 약관 동의 필요

도움말: Docker Desktop은 CLI로도 시작할 수 있습니다.

```bash
docker desktop start
```

Windows에서 서비스로 등록/시작해야 하는 경우(수동 설치 경로):

```powershell
&$Env:ProgramFiles\Docker\dockerd --register-service
Start-Service docker
```

설치 확인:

```bash
docker run -d -p 8080:80 docker/welcome-to-docker
# 브라우저에서 http://localhost:8080 접속
```

## 첫 컨테이너 실행

가장 쉬운 검증 방법은 공식 예제 이미지를 띄워보는 것입니다.

```bash
docker run -d -p 8080:80 docker/welcome-to-docker
```

실행 중 컨테이너 확인/정지/재시작:

```bash
docker ps                # 실행 중 컨테이너
docker ps -a             # 전체 컨테이너(중지 포함)
docker restart <name-or-id>
```

## 이미지 빌드 → 컨테이너 실행 (Node 예제)

### 예제 앱 준비

```bash
git clone https://github.com/docker/getting-started-app.git
cd getting-started-app
```

### 이미지 빌드

```bash
docker build -t getting-started .
```

### 컨테이너 실행 (포트 매핑)

```bash
docker run -d -p 127.0.0.1:3000:3000 getting-started
# http://localhost:3000
```

---

## 데이터 영속화 (Volume)

컨테이너가 삭제되어도 데이터는 유지되도록 볼륨을 사용합니다.

```bash
docker run -dp 127.0.0.1:3000:3000 \
  --mount type=volume,src=todo-db,target=/etc/todos \
  getting-started
```

## Docker Compose 빠른 시작

여러 서비스를 하나의 파일로 정의/실행합니다.

### 프로젝트 생성 및 실행

```bash
mkdir composetest && cd composetest
```

`compose.yaml` 예시:

```yaml
services:
  web:
    image: python:3.11-alpine
    command: sh -c "python -m http.server 5000"
    ports:
      - "8000:5000"
  redis:
    image: redis:alpine
```

실행/확인:

```bash
docker compose up -d
docker compose ps
```

코드 변경 자동 반영(지원 환경):

```bash
docker compose watch
# 또는
docker compose up --watch
```

중지/정리:

```bash
docker compose down
```

## 자주 쓰는 관리 명령

```bash
docker image ls                 # 로컬 이미지 목록
docker ps -a                    # 모든 컨테이너
docker logs -f <name-or-id>     # 로그 팔로우
docker exec -it <name-or-id> sh # 컨테이너 쉘 진입
```

정리(주의: 사용 안 하는 리소스 제거):

```bash
docker system prune -a
```

## 베스트 프랙티스 (요약)

### 1) Dockerfile 캐시 최적화

언어별 의존성 파일을 먼저 복사해 캐시 활용도를 높입니다(예: Go).

```dockerfile
# syntax=docker/dockerfile:1
FROM golang:1.19
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY *.go ./
RUN CGO_ENABLED=0 GOOS=linux go build -o /app/app
EXPOSE 8080
```

### 2) .dockerignore 사용

빌드 컨텍스트에 불필요한 파일을 제외해 빌드 속도/이미지 크기를 개선합니다.

### 3) 멀티 스테이지 빌드

빌드 의존성과 실행 이미지를 분리해 최소 크기의 러ntime 이미지를 만듭니다.

```dockerfile
# syntax=docker/dockerfile:1
FROM --platform=$BUILDPLATFORM golang:alpine AS build
ARG TARGETOS
ARG TARGETARCH
WORKDIR /app
COPY . .
RUN GOOS=${TARGETOS} GOARCH=${TARGETARCH} go build -o server .

FROM alpine
COPY --from=build /app/server /server
ENTRYPOINT ["/server"]
```

### 4) 멀티 플랫폼 빌드 (buildx)

```bash
docker buildx create --use --name mybuild
docker buildx build --platform linux/amd64,linux/arm64 -t user/app:latest .
```

### 5) Compose 사용 시

- `up -d`로 백그라운드 실행, `ps`로 상태 확인, `down`으로 정리
- 변경 시 `--build` 또는 `watch` 사용으로 최신 상태 유지

## 문제 해결 팁

- **포트 충돌**: 이미 사용 중인 포트를 다른 포트로 매핑 (`-p 8081:80`)
- **파일 변경 적용 안 됨**: 이미지 재빌드(`docker compose up --build`) 또는 `watch` 사용
- **권한/경로 이슈(Windows)**: 볼륨/바인드 마운트 경로를 절대경로로 지정, 관리자 권한 확인
